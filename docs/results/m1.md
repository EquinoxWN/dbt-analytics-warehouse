# M1 results

Recorded 2026-10-07 and 2026-10-08 on the author's machine (Intel Core i7-13700H, 13.7 GB RAM,
Windows 11, Python 3.14.5, dbt-core 1.12.5, dbt-duckdb 1.11.0, DuckDB 1.5.6). Other builds ran on
the machine at the same time, so wall times vary between runs. CI re-runs everything on Ubuntu
with Python 3.12.

The results follow DMAIC: the problem and critical-to-quality (CTQ) targets are defined in
[RFC 0001](../rfc/0001-design.md#critical-to-quality-measures-define); this file covers Measure,
Analyze, Improve and Control.

## Reproduce

```bash
make setup    # exact versions from constraints.txt
make data     # daw fetch: the 4 pinned files from datasets.json, size and SHA-256 checked
make build    # daw build: dbt build into data/warehouse.duckdb
make report   # daw report: the JSON summary quoted below
make test     # 58 tests (4 need `make data` first)
make clean-data   # delete the warehouse file and the downloaded data afterwards
```

### Method

- Counts and money come from `marts.audit_trip_outcomes`, `marts.fact_trips` and
  `staging.stg_tlc__green_trips`, read through a read-only DuckDB connection.
- The real-data tests count raw records with DuckDB directly from the parquet files (not
  through dbt) and compare with the audit per file.
- Wall time is `time daw build`; dbt's own timer is the "Finished running ... in" line.

## Analyze

- **The raw data is mostly clean, and the defects are concentrated.** 0.49% of records are
  rejected, but they dominate naive statistics: 89 odometer faults (4,077 to 201,422 miles; no
  record lies between 200 and 4,076 miles) raise the average distance from 2.64 to 20.91 miles.
- **Negative amounts are refunds and disputes, not errors in the trip.** Of 554, 379 have
  payment type 3 (no charge) and 161 type 4 (dispute); 545 have a negative fare. They belong in
  a revenue reconciliation, not in trip statistics, which is why the audit keeps their money.
- **Zero-duration records** (158) mostly have zero distance (133 of 158) but a median total of
  $18.45: likely flat or negotiated fares keyed without running the meter.
- **Out-of-month pickups** (18): two records from 31 December 2008 (a clock reset), 15 trips
  from the previous month filed late and one from 1 April in the March file; the file month is
  the reference.
- **No duplicates and no unknown zones** in these three months. Both rules are still exercised
  by the synthetic data and the unit tests, so they are known to work when they are needed.
- **A residual defect remains in the fact**: 384 trips average above 100 mph (up to 39,168 mph)
  because their duration is a few seconds. They pass all eight rules; M2's accepted-range tests
  decide whether this becomes a rule or a warning.

## Improve

Changes made during M1, each with its measured effect:

| Change | Effect |
|---|---|
| Rejections with one named reason instead of `WHERE` filters (ADR 0002) | 819 records out of `fact_trips`, each counted by reason; average distance 20.91 to 2.64 miles; money reconciles to the cent |
| SQL fixtures for source unit tests (dbt cannot introspect external parquet sources) | The two staging unit tests went from compile errors to passing |
| `pip` in the virtual environment upgraded from 26.1.1 to 26.2.1 | pip-audit: 4 findings (PYSEC-2026-196, PYSEC-2026-3721) to 0 |
| Downloads refuse HTTP redirects (security pass) | A redirect can no longer move a download off the pinned host; covered by a test |
| dbt started with `python -c "from dbt.cli.main import cli; cli()"` instead of `-m dbt.cli.main` | Removes a `runpy` RuntimeWarning from every build log |

## Control

What keeps these results from regressing:

- **CI gates** (`.github/workflows/ci.yml`): install from `constraints.txt`; `make lint`
  (ruff, mypy `--strict`, dbt parse with warnings as errors); download the pinned files (a
  changed file fails on its checksum); all 58 tests; a real-data build whose result is printed
  as a `::notice` annotation and a job summary; pip-audit.
- **Inside every `dbt build`**: enforced contracts on the three star-schema marts, 37 data
  tests (including the reconciliation, money and calendar-gap tests) and 5 unit tests.
- **Mistake-proofing**: the manifest parser refuses unsafe hosts and names; paths placed in SQL
  are checked against an allowed character set; staging cannot read anything but sources, and
  marts cannot be read by intermediate models (`test_project_rules.py`); mutation tests prove
  the unit tests would catch a broken rule.
